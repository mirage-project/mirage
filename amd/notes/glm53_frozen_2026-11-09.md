## Build recipe (CPU only, in the image; `amd/serving/glm/build_glm_libs.sh "T ..." "KINDS"` with `TREE= DLIB=`)

Rules inside the script (flags as `--flag=-D...`):
- `gkdamoe` / `gkdamoelast` T >= 32: `STATIC_GME_WBL2=1`, `STATIC_DRD_STATE_WT=2`;
- `gkdamoe3` T >= 16: `STATIC_GME_WBL2=1`; chains `STATIC_MAX_RESETS=48`, hybrid projections (`CHAIN_HYB=1`, marker `chain_hyb`);
- `gdsa` / `gdsamoe`: sparse-attention splits 8 at T <= 8, else 4.

Defaults in the code (no flag needed):
- `STATIC_DRD_COAL=1` for GLM (`tasks/glm_kda_decode.cuh`; K3's `delta_rule_decode.cuh` keeps 0);
- KDA o_proj finish_all in 4 K parts at T >= 32 (`MPK_OPROJ_FIN`); DSA o_proj store in 4 K parts + allreduce_send at T >= 16
  (`MPK_DSA_OPROJ_KP`); dense MLP down gemm finish_all in 4 K parts at T >= 16 (`MPK_DENSE_FIN`);
- DSA: `MPK_DSA_QB_CAP=128` at T >= 32, indexer score skip (all T), indexer q skip at T <= 16;
- MoE all-reduce: senders land and hand off through LDS from T 4 (`STATIC_ARS_LAND_MIN_T`, `STATIC_ARS_LDSHAND_MIN_T`);
  hc_post_mix's one-thread poll after a push_all / finish_all gemm from T 8 (`STATIC_HCPM_FEWPOLL_MIN_T`).

Flag cleanup 2026-11-10 (commit 8fab0868): the lost probe flags are deleted, the winners are plain code; only the thresholds
(`*_MIN_T`) and the flags the build script sets (`STATIC_GME_WBL2`, `STATIC_DRD_STATE_WT`) stay. Check (CPU, cpu_glmclean5 / 6):
the 61 libraries below built from the frozen tree (mirage_glm194) and the cleaned tree (mirage_glm197) have the same stripped
lib.s (`.loc/.file/.ident/;` lines and `hip_cuid` removed). glm_moe_experts keeps its loop end as `n13 + r2 + rem2`: `ntot`
gave different scalar code at T >= 32 (same registers).

Rebuild the set from scratch (the hook needs all of them; glmab74's server failed without gkdamoe_t1):
`build_glm_libs.sh "1 2 4 8 16 32 64" "gdsamoe gkdadense gkdamoelast gkdamoe gkda gdsa gmoe gdense"` and `"1 2 4 8 16" "gkdamoe3"`
(gkdamoe3 T 32 / 64 do not compile, in the frozen tree either; the hook's chains run at T 1 / 2 / 4 / 16). Run the builds with
`OMP_NUM_THREADS=6` (28 builds at once with the default threads: load ~2800 on 192 cores, no progress in 22 min); each tree
builds in ~50 s. `MPK_RANK_LIB_ASM=1` also writes `lib.s` to compare builds (lib.so md5 differs between builds: hip_cuid).

## Where the time goes at T 64 (KDA + MoE pair, harness, us from the kernel's start)

projection ..18, decode ..45, o_proj (finish_all) ..62, attention all-reduce + hc_post_mix ..85, hc_pre ..92, router ..99, topk
..105, experts (208 experts, ~1.33 GB) ..352 (~233 us from the table at ~5.7 TB/s, the per-CU read rate), MoE send ..365,
hc_post_mix ..375, hc_pre ..381. Measured bounds: the experts phase equals MoE alone on the same routing; the attention
all-reduce is within ~5 us of one synchronized one-shot burst (`amd/bench/hop_once.hip`: 512 / 256 / 128 KB per peer ~14 / 8 /
5 us); the decode reads + writes 128 MB in ~27 us. Left: the ~10 dependent hand-offs per layer (~75 us), the DSA attention
chain (~27 us longer than KDA's), and outside the layer kernels ~230 us per step at bs 64 (logits all-gather 92.5 us at the
link rate, lm_head 51, copies ~45). A per-GPU argmax before the logits gather (greedy only) was not done: it changes SGLang's
sampler path.
